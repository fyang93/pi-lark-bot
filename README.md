# pi-lark-bot

在飞书 / Lark 私聊机器人，或在群里 @机器人，让 [pi](https://pi.dev) 在本机项目中完成任务。

每个私聊用户、每个群聊都有独立的 pi 会话和 Zellij 分屏，保留自己的历史与模型选择。你也可以直接在本机查看进度、继续对话或处理确认操作。

> [!WARNING]
> 机器人可以在本机执行代码。首次使用的用户需要本机确认：默认选中 Confirm，10 秒未确认则拒绝。群内每位用户也需单独授权。所有会话共享项目文件，并非安全沙箱，请限制应用可用范围。

## 要求

- Node.js 22+
- pi 0.85.1+，已配置模型
- Zellij 0.44+
- 飞书或 Lark 开放平台应用（连接时可扫码创建）

## 安装与连接

在目标项目目录安装：

```sh
pi install -l git:github.com/fyang93/pi-lark-bot
```

在 Zellij 中启动 pi；如果 pi 已在运行，先执行 `/reload`。然后输入：

```text
/lark-bot link
/lark-bot on
```

`link` 支持扫码创建新机器人、扫码选择已有机器人，或手动输入 App ID / App Secret。

连接后会自动检查所需权限：

- **已授权**：不弹授权提醒。
- **缺少权限**：弹出已预选缺失权限的官方链接，点击或复制到浏览器，用应用管理员账号确认。
- **检查失败**：提示无法确认，并提供权限链接；已保存的配置不会丢失。

**不会自动打开浏览器，也不会自动授予权限。** 审批或发布要求以开放平台页面为准。二维码换行时可加宽终端，或直接打开同时显示的链接。

安装和连接不会自动监听。首次执行 `/lark-bot on` 后，此项目会记住开启状态；以后在已信任项目的交互式 Pi 中启动时自动尝试监听。`/lark-bot off` 关闭监听并取消自动启动。更换 App ID 不继承开启状态。

## 开放平台设置

在 [飞书开放平台](https://open.feishu.cn/app) 或 [Lark 开放平台](https://open.larksuite.com/app) 确认：

1. 启用机器人，完成应用发布，并设置合适的可用范围。
2. 事件订阅选择**使用长连接接收事件**，订阅 `im.message.receive_v1`。
3. 开通以下权限，并完成所需审批或发布（连接时的权限链接会预选缺失项）：
   - `im:message:send_as_bot`
   - `im:message.p2p_msg:readonly`
   - `im:message.group_at_msg:readonly`
   - `im:message:readonly`
   - `im:message:update`
4. 使用 `/model` 按钮菜单时，启用回调订阅 `card.action.trigger`。
5. 群聊使用前，将机器人加入群。

## 日常使用

- 私聊直接发文字；群聊需要 @当前机器人，同一群共享会话。
- 回复一条文件、图片、音频或视频消息并附上文字要求，即可让 pi 读取附件。单个附件上限 100 MB；单独发送附件不会启动任务。
- 消息授权后直接交给对应 Pi 会话；Pi 忙时进入原生 follow-up 队列，不等待上一条回复完成。一条输入不再绑定一张回复卡片，输出按聊天转发，子代理的后续回复也一样。
- 飞书中会显示处理进度和助手回复，不转发模型思考内容或原始工具输出。**Lark 专属分屏是共享输出通道，在该分屏本地输入所产生的助手回复也会转发；本机主 pi 的对话不会自动转发。**
- `Lark: … pending handoff` 只表示尚未交给 Pi 的消息，不是运行中的模型任务数。投递确认不代表执行完成；投递状态不确定时不自动重试，以免重复执行。
- 对话分屏不会因空闲而自动关闭；后续消息复用同一分屏。手动关闭后，下次消息会重新打开并继续原来的历史和模型。
- 停止监听会关闭机器人分屏、丢弃未执行队列，但保留聊天历史。
- 在**本机主 pi** 中执行 `/new`，若项目已开启自动监听，新会话会自动恢复。切换期间会短暂断开、关闭机器人分屏并丢弃未执行队列，聊天历史保留。
- 切换、分叉会话、`/reload` 或退出仍会停止当前监听；之后启动的已信任项目交互式 Pi 会尝试恢复。项目锁和私有 socket 身份校验保证同一项目只有一个入站 listener，其他 Pi 不会抢占；仅已确认进程退出且端点不再响应时自动回收旧锁，响应超时或身份不明时保守拒绝启动。

### 本机 pi 命令

| 命令 | 说明 |
| --- | --- |
| `/lark-bot` | 查看连接、监听和会话状态 |
| `/lark-bot link` | 连接或更换机器人 |
| `/lark-bot on` | 开始监听，并记住自动启动偏好 |
| `/lark-bot off` | 在当前 owner 会话停止监听、取消自动启动，保留历史；有其他 owner 时须去 owner 会话执行 |
| `/lark-bot allow` | 从最近被拒绝的用户中选择授权 |
| `/lark-bot allow <open_id\|授权码>` | 手动授权用户 |
| `/lark-bot deny <open_id\|授权码>` | 移除用户授权，下一条消息起生效 |
| `/lark-bot push` | 查看推送目标 |
| `/lark-bot push off` | 清除推送目标 |

用户被拒绝时会收到授权码，可交给本机操作者授权。未开始监听时也能用完整 `open_id` 预先添加用户。

### 飞书聊天内命令

| 命令 | 说明 |
| --- | --- |
| `/stop` | 请求 Pi 中断当前操作，保留历史和分屏；不负责清空或重新调度 Pi 原生队列 |
| `/new` | 关闭当前私聊或群聊的分屏并重置历史，丢弃该 Pi 会话的未执行消息 |
| `/model` | 查看、选择模型 |
| `/model provider/model` | 指定模型，保留历史；当前分屏会重启，未执行消息不会迁移 |

### 主动推送

在目标聊天里告诉机器人：“以后把消息推送到这里。”之后可让 pi 或 skill 使用 `lark_push` 主动发送通知、报告。

每个项目只有一个推送目标，未设置时不能推送。同项目各本机 Pi 会话均可使用 `lark_push`；非监听会话经本机私有 IPC 交由唯一监听者处理，共享当前目标和每分钟 20 张的限流。监听者关闭或不可用时推送报错。单次推送最多 4 张卡片。

## 更新与排查

在目标项目执行 `pi update --extensions` 即可更新。如需手动重启 listener，可在 owner Pi 中依次执行：

```text
/lark-bot off
/reload
/lark-bot on
```

没有收到回复时，先用 `/lark-bot` 检查状态，再检查白名单、应用可用范围和开放平台设置。

**同一个应用不要在多个项目或机器上同时监听**，否则消息可能被其他实例接收。仍有问题时，查看本机 pi 的提示、机器人分屏和开放平台的事件/API 日志。

凭据、白名单、附件和会话历史保存在项目的 `.pi/lark-bot/`，自动排除在 Git 之外。内容为本地明文，请勿分享或提交该目录。

## 开发

```sh
npm install
npm run typecheck
npm test
npm run test:integration
npm pack --dry-run
```

集成测试使用独立 Zellij 会话和本地模拟模型，不消耗付费模型额度；需要 Zellij 0.44+ 和 util-linux 的 `script`。真实平台审批和显示效果需用自己的应用验收。
